- 引擎：v1 = B1 等价旧引擎；v2 = `pipeline.remember.cluster_convergence` + `window_batch_alignment`（LME 实验后已切默认，commit 8fa9651）
- 评分：官方 scorer（MemoryAgentBench @455306d，judge=kimi-k3，entity2id 同一 sha256），Overall = 四域均值（AR/TTL/LRU/SF）

## 四、配置差异披露（对比公平性）

两 run 同采样、同 judge、同 scorer commit、同 entity2id，但 v2 运行期打了以下鲁棒性补丁（commit db81ee1）与配置升级：

| 项 | v1 | v2 |
|---|---|---|
| max_tokens（输出预算） | 16,384 | 32,768 |
| context_window_tokens | 32,000 | 262,144 |
| extract JSON 重试 | 2 | 5 |
| llm.timeout_seconds | 300（含被硬编码覆盖 bug） | 1200 + 继承修复 |
| documents.absolute_path | 不落库（缓存 miss） | 落库（断点续传生效） |

影响评估：32k 输出消解了 v2 每晚 ~222 次 extract 截断重试（截断重试会计入 calls，v2 少算的是"本不该发生的重试"，方向上对 v1 不公平的幅度很小且利于 v1）；completion tokens 只降 -5% 说明 v2 并未靠"少写内容"省预算。timeout/重试/absolute_path 三项只影响可达性不影响产出质量；v1 同样存在缓存 miss 与超时崩溃（重跑成本更高），对比公平性未破坏。

## 五、结论

1. **靶点验证通过**：TTL MCC 0.43→0.46、FC-MH 0.67→0.70，v2 的簇收敛在两个短腿域均为正向。
2. **整体持平略降**（pi -0.018），全部来自 LRU Summ 单题翻转（n=1 噪声）；辅轨 skill-agent/baseline 双涨。
3. **成本近半**：calls/doc -46%、总 tokens -18%，与 LME 结论（calls/doc -65%）方向一致、幅度略缓（MAB 文档更长、收尾收敛占比更高）。
4. **知识库质量更干净**：重复家族率 0.20→0.00。
5. 建议：v2 维持默认引擎；LRU Summ 域在全量（非 sampled）跑之前不值得单独优化（n=1）；TTL/FC-MH 距满分仍有空间（0.46/0.70），下一个抓手在窗口内事实覆盖的原子事实抽取密度，而非对齐合并。
