\section{引言}

设想一个约朋友吃饭的场景。几个月前，她说：“我不吃海鲜，最近也在少吃辣。”上周，她又说：“现在可以吃辣了。”再次选餐厅时，如果只记得“她有忌口”，就不知道哪一项发生了变化；如果只记住最新一句，又会遗漏仍然有效的海鲜忌口。一次有效的回忆需要把两次谈话关联到同一个人，区分已经改变和尚未改变的偏好，并保留“最近”“少吃”这样的限定词。

智能体面对不断增长的历史，也需要完成这样的回忆：迅速定位相关事件，同时保留决定未来答案的细节。固定摘要可能在问题尚未出现时就省略这些细节，而每次重读全部历史又会花费大量精力处理无关内容。Deep-Dream 将这一问题分为两个相互配合的过程：先定位相关记忆，再按需读取回答所需的原始证据。

Deep-Dream 是一个面向智能体长期记忆的文档优先时序概念图谱。这里“文档优先”指：原始文档和精确源文本跨度是权威证据，图只是导航索引。更具体地说：

\begin{itemize}
    \item \textbf{时序}：图只有一条状态轴——观测时间。新输入追加观测，必要时创建新版本；事件日期保留在观测内容中，而不是成为第二条状态时间线。更新绝不覆写它所替换的事实，新旧事实都保持能被找到。
    \item \textbf{概念}：实体和关系概念是稳定句柄，不是事实容器。每个概念记录提到它的观测，并指向精确源文本跨度。概念可以被重读、重审，但不会被压缩成摘要。
    \item \textbf{图谱}：这里的图不是知识图谱。知识图谱的节点和边本身承载事实、就是权威；Deep-Dream 的图只是导航层。文档与源文本跨度才是权威；会话片段、实体与关系概念、观测和版本链接构成一个派生状态，只回答“下一步应该打开哪个源”。
\end{itemize}

查询时，智能体可以搜索、遍历、读取和验证。引用检查只接受由当前读取路径浮现出的源标识符。因此，对齐错误可能降低覆盖率，但它无法让一句未被观测的派生句子被算作读取证据。

身份解析是渐进的。首次对齐不确定时，系统允许一个实体暂时保持为多个候选族；后续观测和关系邻域可以降低身份不确定性并重定向指针，而不删除证据。例如，早期记录只写着“Alex 批准了合同”，但库中可能同时有实验室的 Alex 和供应商的 Alex，系统就先保留两个候选族。后来出现“实验室的 Alex 与刘博士共同汇报项目”和“供应商的 Alex 续签了账户”等信息，组织和关系线索使指针逐步分开，而无需修改任何原文。若一开始就把两人合并，查询其中一人时就可能把另一人的合同和项目经历一起取出。这样，修正在安全性上优于过早合并。

两种写入程序的区别在于实体身份何时最终确定。初始版本（Base）在每个窗口到达时立即决定身份；修订版本（Align+）先保存观测和候选匹配，等周围的证据处理完后再合并兼容的实体。两者生成同一种图。

从信息论看（\cref{sec:information-view}），固定摘要在问题未知之前就提交了一次有损重构，而 Deep-Dream 把“读多少原文”的预算推迟给智能体：对简单查询可以停在紧凑的概念邻域，不确定性仍高时则花更多预算去读会话片段、关系和源文件。

这些设计提出五个可检验的预测：逐步读取原文应当有助于合并多次提及或处理后来出现的修正；观测时间和版本链接应当让旧信息与新信息同时可查；概念和关系链接应当把分散在不同会话片段中的证据连接起来；只追加、不删除的存储在删除事实时会失败；延迟实体对齐应当减少重复实体族和入库成本，即使不一定提高所有准确率。

四个基准分别覆盖不同能力。MemoryAgentBench（MAB）让三种回答方式使用相同的问题和记忆库，区别在于如何找到支持答案的原文：一次性拿到固定检索结果；多次调用只读搜索工具；或者直接打开原始文件并核对引用。LongMemEval 先把一批对话完整写入系统，再测试旧信息和后来修正能否同时找到。LoCoMo 使用二值 $J$ 评分，分别包含单跳、多跳、时间变化和开放域问题。MEME 测试被删除的信息、与删除内容相关的信息，以及原本不存在的信息。匹配运行比较初始和修订后的写入程序。

我们的贡献是：
\begin{itemize}
    \item \textbf{表示}：Deep-Dream 以文档为权威，用概念、关系、观测和版本构成按观测时间排序、可重建的检索索引。
    \item \textbf{回答与引用检查}：智能体控制搜索、图扩展、源读取、验证与停止；检查步骤保证每条引用都能回到实际读过的原文。
    \item \textbf{信息论视角}：解释为什么导航信息和原文信息应当分开，并说明查询时如何决定读取多少。
    \item \textbf{分项能力评测}：MAB、LongMemEval、LoCoMo 和 MEME 分别测试不同回答方式、信息更新、跨片段关联和删除能力，而不是把它们塌缩成一个分数。
    \item \textbf{不同基准上的比较}：保留各项测试条件，解释与已发表记忆系统的分数差异，并报告修订引擎（Align+）的成本/整合权衡与负面结果。
\end{itemize}

三种回答方式同时改变工具、提示词和算力，因此它们比较的是完整系统，不能据此估计某个单独组件的因果作用。MAB 将冻结的 Base 配对样本与原地扩展的 Align+ 样本进行比较；同模型的完整上下文结果只覆盖严格字符预算内的题目，作为实测参照。这里的时序模型是记忆表示和修订原则，并未实现完整的当前值、时点值或撤回语义。
