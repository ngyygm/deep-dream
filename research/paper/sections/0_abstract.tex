Long-term memory is difficult because a growing history must stay easy to search without losing the exact wording needed for a later answer. Loading that history into a finite context window is a memory-management problem: what enters the window should be addressed, not bulk-copied. Deep-Dream supplies the address structure: original documents and exact passages are the factual record; concepts, relations, observations, and version links narrow where to look; at query time, an agent opens and checks only the source text the question needs. If an early mention does not identify which entity it refers to, the system keeps multiple candidates, and later observations can redirect the links without rewriting the source. We evaluate on MemoryAgentBench, LongMemEval, LoCoMo, and MEME. On MemoryAgentBench, under one model and one scorer, answering from a single retrieval result scores 0.333, answering through read-only memory tools 0.400, and answering from source text the agent has actually opened 0.710, with the margin concentrated on multi-mention and update questions; a same-model full-context reference bounds what selective reading still misses. Published Mem0 and Zep scores on LoCoMo and LongMemEval use different judges and rubric versions and serve as background, not controlled comparisons. In paired runs, the revised write implementation, which records observations first and merges compatible identities only after more context is available, reduces write requests per document by 46--65\% at similar sampled quality.
