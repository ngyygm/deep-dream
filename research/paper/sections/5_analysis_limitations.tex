\section{Analysis and Limitations}
\label{sec:analysis}

The problem is keeping a growing record searchable and trustworthy when a query reads only part of it. Summary-only memory loses wording at write time; graph-only memory can mistake derived links for facts; full-context prompting pays for every document. Deep-Dream separates three responsibilities: concepts and relations locate candidates, observations and source spans authorize facts, the agent decides how much to open.

This separation changes what the graph is judged on: it need not contain the answer or lift offline top-ten recall by itself, only route reading to document groups, versions, and related episodes. The channel replay supports this interpretation: the graph is an address layer, not a second fact store. MAB gains on questions that join mentions or check updates support navigation plus source reading, and LoCoMo adds the case where relation paths connect episodes while linked text remains the authority. The same runs price the trade: loading everything wins only where it fits and scores nothing beyond its budget; addressed reading pays for indirection and has no capacity cliff.

Progressive alignment addresses a different question: how should identity uncertainty be handled at an ambiguous first mention? Keeping two candidates preserves recoverable uncertainty; later observations redirect pointers and merge compatible families without rewriting evidence. An early wrong merge contaminates one address with two histories and is harder to undo. Align+ is therefore a revision policy, not merely a faster extractor. Its lower call counts and fewer duplicate families are consistent with less repeated work, but bundled concurrency and runtime changes prevent a component-level causal claim.

The temporal principle gives memory a precise state axis: processing/observation time orders versions, while event dates remain content in the observations. New information adds a version or pointer and leaves the old span available, so an earlier statement and a later correction stay jointly searchable, preserving the history that explains change but not specifying which observations a deletion should suppress. MEME exposes that missing operation: temporal revision and deletion are distinct capabilities.

At read time, the model predicts adaptive allocation rather than one fixed summary size (\cref{sec:information-view}): the address term of \cref{eq:two-rate-code} is cheap and lossy enough to navigate, the source term supplies the answer's wording, a local question stops early while a multi-hop, update, or conflict question expands relations and reads more spans; \cref{eq:answer-decomposition} separates finding failures from verification failures. Current results support source reading and revision-aware writing but do not measure entropy reduction directly.

Evidence has limits: MAB paths are complete-system comparisons, not single-component interventions; LongMemEval and LRU subsets are small; and published cross-system rows use different models, judges, and subsets. The equations describe intended information flow, not measured gains or an optimality proof. The citation gate confirms that an opened span was returned by a tool, not that it entails the answer. Future work should measure entity uncertainty, merge contamination, fixed-read-budget accuracy, deletion and as-of-time behavior, conflict handling, and confidence calibration.
