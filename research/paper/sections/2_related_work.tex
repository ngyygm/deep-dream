\section{Related Work}

\paragraph{Long-term conversational memory benchmarks.}
LoCoMo evaluates very long-term conversational memory across single-hop, multi-hop, temporal, open-domain, and adversarial questions, and its original evaluation reports normalized token-F1 rather than a single universal LLM judge \citep{maharana2024locomo}. LongMemEval expands the problem into information extraction, multi-session reasoning, temporal reasoning, knowledge updates, and abstention over 500 questions \citep{wu2025longmemeval}. MEME targets a different failure regime: multiple entities and evolving state, including deletion, cascade, and absence tasks that are difficult to capture with static retrieval metrics \citep{jung2026meme}. MemoryAgentBench further frames memory as incremental multi-turn interaction with retrieval, test-time learning, long-range understanding, and selective forgetting \citep{hu2025memoryagentbench}. BEAM tests long coherent conversations at up to millions of tokens \citep{tavakoli2026beam}. These benchmarks are complementary rather than interchangeable. Deep-Dream therefore reports question count, subset, metric, answerer, and judge for every result.

\paragraph{Structured memory systems.}
MemoryBank and MemGPT established early baselines for persistent memory and context management. A-MEM organizes experiences as linked atomic notes with keywords and contextual descriptions \citep{xu2025amem}. Mem0 focuses on production-oriented incremental memory operations and reports LoCoMo results with an LLM-based judge \citep{chhikara2025mem0}. Such systems make derived memory a first-class object because compression improves cost and retrieval. Deep-Dream shares the need for compact navigation, but uses a stronger authority distinction: a derived memory node can suggest where to look, while the source episode or turn remains the object that the query path must expose and submit.

\paragraph{Temporal and graph memory.}
Zep's Graphiti architecture represents entities and relationships in a temporal knowledge graph and reports results on DMR and LongMemEval \citep{rasmussen2025zep}. Its design makes temporal indexing and graph traversal central to memory retrieval. Deep-Dream also stores relation assertions, timestamps, and concept neighborhoods, but does not treat this overlap as a claim that one architecture is universally safer or more accurate. Our system uses the graph as an auditable overlay over documents and records an active/incomplete publication boundary. This allows us to ask whether a candidate is supported by a current source span, while retaining historical observations for later analysis.

\paragraph{Evidence and provenance.}
Retrieval-augmented systems commonly use dense or sparse indexes to select text for generation. The provenance question is often left to the prompting layer: a model receives retrieved context, but the runtime does not always know whether the final evidence was actually observed, belonged to the intended user, or was still active after an update. Deep-Dream makes this runtime contract explicit through scope-isolated tools, fresh context per question, read-only access, and evidence submission validation. This contract is narrower than a semantic fact verifier. It prevents invalid evidence identifiers and scope violations, while answer--evidence entailment, abstention quality, and malicious derived-memory robustness remain separate experiments.

Our positioning is therefore orthogonal to a simple ``graph versus vector'' comparison. The paper studies the boundary between a useful navigation index and an authoritative source, then evaluates the boundary with both end-task QA and retrieval/evidence diagnostics.
