\section{Introduction}

An agent's memory is not only a database lookup problem. When a system answers ``What did the user decide last month?'', a useful answer must identify a relevant event, distinguish it from later changes, and make the underlying source inspectable. A compressed fact can be semantically useful while still being a poor authority: an extraction error can be copied into a graph, a merge can erase a prior state, and an inactive record can remain retrievable after a deletion. These failure modes are especially important in long-running assistants, where memory is updated incrementally and answers are generated long after the original interaction.

Recent systems take complementary approaches. Mem0 maintains incremental memories with update operations and evaluates them on LoCoMo \citep{chhikara2025mem0}. Zep presents Graphiti, a temporal knowledge-graph engine, and evaluates retrieval on Deep Memory Retrieval and LongMemEval \citep{rasmussen2025zep}. These systems show that structured memory can improve long-context question answering. They also motivate a design question that is less visible in a single accuracy number: which part of the memory is allowed to authorize an answer? Deep-Dream answers this question by separating navigation from authority. The original document or conversation turn remains the source of truth. Concepts, relations, observations, and search summaries are derived overlays that point back to source spans.

This separation changes the system contract. A query can use a graph neighborhood to find a candidate, but the final agent trajectory must read source-level material and submit evidence identifiers that were returned within the current scope. The contract prevents a class of provenance and cross-scope errors without claiming that a valid identifier entails the generated answer. Semantic answer--evidence consistency is an explicit evaluation target for future controlled experiments, not an assumption hidden in the interface.

We make three contributions.

\begin{itemize}
    \item \textbf{An auditable memory substrate.} We implement a document-first model with episodes, stable concept families, versioned observations and assertions, conservative alignment, provenance, and atomic publication. Derived nodes remain rebuildable navigation structures.
    \item \textbf{A source-bounded query path.} We combine lexical, semantic, concept, relation, and neighborhood retrieval with fine-grained source expansion. A conversation-scoped, read-only tool interface validates that submitted evidence was actually exposed to the agent and belongs to an active scope.
    \item \textbf{A protocol-aware evaluation.} We report full LoCoMo-1986 token-F1, LoCoMo-1540 Mem0-compatible accuracy, LongMemEval-S-500, LoCoMo-Plus, and MEME. We additionally expose channel, source-expansion, judge-sensitivity, and failure diagnostics. For the LoCoMo $J$ comparison we go one step further: we run Mem0's exact binary CORRECT/WRONG judge protocol with Kimi-K3 substituted for GPT-4o-mini as both answerer and judge, so Deep-Dream's $J$ (95.19\%, single run) sits in the \emph{same} column as Mem0's published $J$ rather than in a separate one.
\end{itemize}

The strongest current evidence is deliberately scoped. Deep-Dream obtains 95.19\% on the 1,540-question LoCoMo protocol under Mem0's $J$ metric with K3 as both answerer and judge (94.22\% under an independent Qwen3.7-plus cross-judge on the same K3 answers; 98.51\% cross-judge agreement), 93.18\%/93.57\% under the local Qwen3.7-plus/Kimi-K3 cross-judge setup, and 84.60\% on LongMemEval-S. The $J$ result shares Mem0's metric (differing only by model---K3 for GPT-4o-mini---and being a single run versus Mem0's 10-run mean$\pm$std), and carries a disclosed diagnostic-fingerprint caveat; we therefore present it as protocol-matched context, not a superiority claim over Mem0 or Zep. Instead, our analysis isolates what the current system supports, what it does not support, and which controlled experiments are required next. \Cref{fig:architecture} summarizes the design.

The rest of the paper describes the memory model and query contract, presents the protocol-aware experiments, analyzes retrieval and negative-memory behavior, and closes with limitations and a concrete submission gate.
