\section{Deep-Dream}
\label{sec:deep-dream}

\subsection{Memory model}

Let $D$ be a source document and $e_i$ an episode extracted from one of its spans. The persistent state is
\[
M_t=(F_t,O_t,G_t),
\]
where $F_t$ contains stable concept families, $O_t$ is an append-only store of observations with source spans, and $G_t$ contains relation, neighborhood, and version links. Deep-Dream keeps $D$, episodes, versions, and exact source offsets as authoritative data. An entity family $f$ is a search handle; each observation $o_{f,i}$ records what a source asserted, when it was observed, and where it can be reread. Relations use the same distinction between a derived link and the assertion that supports it. Active and historical observations remain distinguishable, so an update adds a pointer or version rather than overwriting source text.

The graph has one state axis: processing/observation time. An event date can remain in the source observation and can be used during retrieval, but it is not a second version clock. This choice keeps version order well-defined while preserving the temporal language that the document actually contains.

\subsection{Ingestion and alignment: two engine generations}

\textbf{Base and Align+ differ in when entity identity is committed.} They construct the same kind of graph over the same document representation. Base aligns and consolidates each window as it arrives, without a final reconciliation. Align+ separates evidence capture from identity commitment: windows are ingested concurrently, candidate matches remain open, and compatible families are merged only after all windows in the current task group have been processed. In plain terms, Base is \textquotedblleft decide now\textquotedblright; Align+ is \textquotedblleft record first, decide later with more context\textquotedblright.

The Remember pipeline performs heading-aware chunking, validated entity/relation extraction, conservative family alignment, batch candidate review, and final consistency pass. Over-splitting is recoverable because every observation keeps its source link. A later merge redirects compatible pointers; it does not rewrite or delete the observations that motivated the earlier split. A premature wrong merge is more dangerous because it makes two entities share one search entry before their evidence can be separated.

\subsection{How answers obtain evidence}
\label{sec:answer-paths}

All three methods use the same question stream, frozen libraries, scorer, answerer configuration, and task-group eligibility rule where the protocol permits. They differ only in how they obtain supporting text:
\begin{enumerate}
    \item \textbf{Direct retrieval.} The system returns one fixed set of lexical, semantic, and graph matches. A separate answerer sees that set once and cannot ask for more.
    \item \textbf{Tool-assisted reading.} The agent may call read-only search and record tools several times. The resulting records are then given to a separate answerer; this method does not open the original files.
    \item \textbf{Source reading.} The system selects a relevant document group, the agent opens the original files with ordinary tools, and the answer cites only spans that it actually read.
\end{enumerate}

Because tools, prompts, and compute change together, these are comparisons of complete systems rather than single-component interventions. A separate channel replay changes only the derived search channels.

A citation check runs without an LLM. It accepts a source identifier only when the current question's tools returned it, it belongs to an eligible document group, and the system still has a pointer to the original text. This confirms that the citation came from text the agent opened; it does not guarantee that the text is relevant. The runtime records tool observations, source IDs, latency, exit status, and code/runtime hashes.

Candidate records combine lexical, semantic, concept, relation, and neighborhood channels by reciprocal-rank fusion and resolve to episodes and spans. In the source-reading method, the graph chooses where to read; it does not manufacture the content that is read.

\subsection{Progressive disclosure in information-theoretic terms}
\label{sec:information-view}

\textbf{Write time: information is retained.} Let $X_{1:t}$ be observations extracted from the first $t$ source spans, $Z$ their latent entity assignments, and $M_t=(F_t,O_t,G_t)$ the persistent state. Ingestion adds an observation and may redirect a family, but does not delete one:
\begin{equation}
  \begin{aligned}
  O_{t+1}&=O_t\cup\{(X_{t+1},\mathrm{span}_{t+1})\},\\
  I(Z;O_{1:t+1})&=I(Z;O_{1:t})+
  I(Z;X_{t+1}\mid O_{1:t})\ge I(Z;O_{1:t}).
  \end{aligned}
\end{equation}
The equality is bookkeeping for the append-only observation stream, not a measured entropy gain. It explains why first-pass alignment can remain provisional: later evidence may refine the family partition while preserving the source material.

\textbf{Read time: navigation plus source text.} For a query $q$, let $A$ be the compact search record returned by concept families and relation paths, $E_C$ the exact spans opened from candidate set $C$, and $Y$ the answer-relevant fact:
\begin{equation}
  I(Y;A,E_C\mid Q=q)=I(Y;A\mid Q=q)+I(Y;E_C\mid A,Q=q).
  \label{eq:two-rate-code}
\end{equation}
The first term is the information used to find a candidate; the second is the additional fact information obtained by opening source text. A summary-only system replaces the source $S$ by a write-time channel output $f(S)$ and may lose details needed by a later query. Deep-Dream keeps $S$ available for later reading and lets the agent choose how much to read. This is an interpretation of the interface, not a claim that the implementation solves a variational bottleneck objective.

\textbf{The agent chooses reading depth.} Reading forms a chain $C_0(q)\subseteq C_1(q)\subseteq\cdots\subseteq S$ under policy $a_{k+1}=\rho(q,M_t,C_{\le k},u_k)$, where $u_k$ is current uncertainty. Every cited span belongs to $S$, so the citation check confirms that the cited text was opened; the remaining failure mode is that the relevant text was never found, in which a relevant span never enters $C_k$. If $R_q$ denotes finding the relevant span and $V_q$ denotes successful verification after reading it,
\begin{equation}
  \Pr[\widehat Y=Y\mid q]\ge \Pr[R_q\mid q]\,\Pr[V_q\mid R_q,q].
  \label{eq:answer-decomposition}
\end{equation}
This factorization predicts that the graph should help locate evidence, while additional source reading should matter most when the answer joins mentions, resolves an update, or checks a conflict.
